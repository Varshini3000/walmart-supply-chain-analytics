# Walmart Supply Chain Analytics — Data Dictionary

## Dataset Overview

The **Walmart Supply Chain Analytics** dataset contains multiple relational tables used to analyze sales, orders, products, inventory, shipments, stores, suppliers, and warehouse operations.

The dataset is connected to **MySQL** and imported into **Power BI** for data modeling, DAX calculations, KPI development, and interactive dashboard analysis.

The project contains **7 tables**:

* `inventory`
* `orders`
* `products`
* `shipments`
* `stores`
* `suppliers`
* `warehouse`

---

# 1. Inventory Fields

### `inventory`

| Column         | Data Type      | Description                                    | Example    |
| -------------- | -------------- | ---------------------------------------------- | ---------- |
| `InvetID`      | Whole Number   | Unique identifier for each inventory record    | 10001      |
| `InvetDate`    | Date           | Date associated with the inventory record      | 2025-05-30 |
| `ProductID`    | Whole Number   | Identifier of the product                      | 101        |
| `StoreID`      | Whole Number   | Identifier of the store                        | 25         |
| `WarehouseID`  | Whole Number   | Identifier of the warehouse                    | 5          |
| `OpeningStock` | Whole Number   | Stock available at the beginning of the period | 500        |
| `RecievedQty`  | Whole Number   | Quantity received during the period            | 200        |
| `SoldQty`      | Whole Number   | Quantity sold during the period                | 150        |
| `ClosingStock` | Whole Number   | Stock remaining after sales                    | 550        |
| `ReorderLevel` | Whole Number   | Stock level at which replenishment is required | 100        |
| `StockStatus`  | Text           | Current stock condition                        | In Stock   |
| `InvetValue`   | Decimal Number | Monetary value of inventory                    | 25000      |

> **Note:** `WarehouseID` is a **Whole Number** because it is an identifier used to establish relationships with warehouse-related data.

# Power BI Derived Measures

The project uses DAX measures to create the main dashboard KPIs.

| Measure               | Description                               |
| --------------------- | ----------------------------------------- |
| `Total Sales`         | Total sales generated across orders       |
| `Total Orders`        | Total number of orders                    |
| `Total Quantity`      | Total quantity ordered/sold               |
| `Average Order Value` | Average sales value per order             |
| `Delivered Shipments` | Number of shipments marked Delivered      |
| `Delayed Shipments`   | Number of shipments marked Delayed        |
| `Delayed Shipment %`  | Percentage of shipments that were delayed |
| `Total Suppliers`     | Total number of suppliers                 |
| `Inventory Value`     | Total inventory value                     |
| `Closing Stock`       | Total closing inventory quantity          |
| `Received Quantity`   | Total quantity received                   |
| `Reorder Items`       | Inventory records requiring reorder       |

# Data Model

The project uses relationships between the seven tables to connect products, stores, inventory, orders, shipments, suppliers, and warehouses.

```text
                         Products
                            |
             +--------------+--------------+
             |              |              |
             ↓              ↓              ↓
         Inventory        Orders       Shipments
             |              |              |
             ↓              ↓              ↓
          Stores -------- Orders -------- Shipments
             |
             ↓
         Warehouse

        Suppliers
             |
             ↓
         Shipments
```

The relationships allow Power BI to analyze supply-chain performance across different business dimensions.
